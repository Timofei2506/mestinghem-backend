# Безопасность и защита данных

Этот документ описывает подход платформы **Mestinghem AI** к безопасности, защите данных и устойчивости сервиса. Мы проектируем систему по принципу «безопасность по умолчанию и на уровне архитектуры».

- Оператор: **Mestinghem AI UAB**, Vilnius, Lithuania
- Контакт по безопасности: **security@mestinghem.ai**
- Версия: 1.0

## 1. Управление доступом и аутентификация

- Пароли хранятся исключительно в виде необратимых криптографических хэшей с индивидуальной солью; восстановление пароля невозможно, возможен только сброс.
- Доступ к API обеспечивается короткоживущими токенами с ограниченным временем действия и механизмом обновления сессии.
- Поддерживается двухфакторная аутентификация (TOTP) для защиты учётной записи.
- Неудачные попытки входа ограничиваются, а аккаунт может быть временно заблокирован для предотвращения перебора.
- Личные API-ключи выдаются пользователем по запросу, хранятся в виде хэшей и могут быть отозваны в любой момент.

## 2. Разрешительная модель модулей

Доступ к чувствительным модулям (терминал, управление устройством) регулируется отдельными разрешениями. Пользователь явно включает только те возможности, которые ему нужны. По умолчанию рискованные функции отключены.

## 3. Изоляция выполнения (песочница терминала)

Команды терминала выполняются в изолированном рабочем пространстве, привязанном к учётной записи пользователя. Действуют политики безопасности, которые блокируют:
- попытки выхода за пределы песочницы и обращения к системным путям;
- разрушительные операции (удаление корневой файловой системы, форматирование);
- загрузку и выполнение сторонних скриптов из недоверенных источников;
- действия, требующие повышения привилегий.

## 4. Безопасность управления устройством

Подключение агента для управления вашим компьютером построено на принципах явного согласия и минимальных привилегий:
- устройство проходит сопряжение по одноразовому короткоживущему коду и уникальному ключу;
- команды подписываются и проверяются на подлинность;
- выбран профиль разрешений, ограничивающий набор допустимых действий;
- рискованные и критические действия требуют вашего явного подтверждения и не выполняются автоматически;
- операции, способные нанести непоправимый вред, запрещены полностью.

Подробнее — в Политике управления устройством.

## 5. Защита данных

- Шифрование при передаче по всем соединениям (TLS).
- Ограничение доступа к данным по принципу наименьших привилегий.
- Хранение персональных данных в юрисдикциях с адекватным уровнем защиты либо при наличии стандартных договорных положений.
- Регулярное резервное копирование и возможность восстановления.
- Разделение данных пользователей; доступ к чужим данным технически исключён.

## 6. Безопасность приложений

- Входные данные проверяются и очищаются; выходные ответы проходят санитизацию.
- Применяются заголовки безопасности HTTP и ограничения источников запросов.
- Зависимости обновляются, известные уязвимости устраняются.
- Ведётся журнал аудита значимых событий для расследования инцидентов.

## 7. Мониторинг и реагирование на инциденты

Мы отслеживаем события безопасности и аномалии. При инциденте, способном повлечь высокий риск для прав и свобод пользователей, мы уведомляем надзорный орган в течение 72 часов, а затронутых пользователей — без неоправданной задержки, как того требует GDPR.

## 8. Ответственное раскрытие уязвимостей

Мы приветствуем сообщения исследователей безопасности. Порядок описан в документе «Ответственное раскрытие уязвимостей». Сообщайте о найденных проблемах на **security@mestinghem.ai**.

## 9. Ответственность пользователя

Безопасность — общая задача. Не передавайте учётные данные третьим лицам, используйте стойкие уникальные пароли, включайте двухфакторную аутентификацию и выдавайте агенту только необходимые разрешения.
